# 01 系统架构

Status: Draft

系统目标：

- 第一版优先保证可调试、可恢复、可验证
- 以 H618 为主控，围绕启动、供电、存储和外设扩展构建
- 所有高风险项优先暴露为文档约束，而不是直接写死在实现里

系统模块：

- `J1`：`USB-C 5V` 输入
- `F1`、`D1`：输入保护
- `U1`：`AXP313A` 或等效 PMIC
- `U2`：Allwinner H618 SoC
- `U3`：2GB LPDDR4
- `U4`：SPI NOR Flash
- `J2`：MicroSD 启动座
- `U5`：千兆以太网 PHY
- `U6`：USB2.0 Hub
- `J3`：调试串口
- `J4`：26Pin 扩展口
- `SW1`、`SW2`：复位和 FEL / BOOT 按键
- `J5`：协处理器预留口
- `J6`、`J7`、`J8`、`J9`：以太网、USB 和显示输出

系统分层：

1. 电源层
- 负责把 `5V` 输入转成 `3V3 / 1V8 / 1V1_CORE / 1V2_DDR / 0V9_DDR`
- 所有关键电源都要有测试点

2. 启动层
- 负责 `MicroSD`、`SPI NOR`、`FEL`
- 这一层决定板子能否恢复、能否量产调试

3. 计算层
- `U2` 与 `U3` 构成主计算域
- `U1` 负责电源时序和基础控制

4. 外设层
- `U5` 负责以太网
- `U6` 负责 USB Host 扩展
- `J4` 和 `J5` 提供二次扩展能力

5. 人机与调试层
- `J3` 提供串口日志
- `SW1`、`SW2` 提供复位与恢复入口

首版启动链：

- 上电后由 `U1` 建立基础电源
- `U2` 先通过 `MicroSD` 或 `SPI NOR` 进入启动流程
- `UART0` 必须尽早输出日志
- 如果启动失败，必须可通过 `FEL` 进入恢复模式

设计原则：

- 调试能力优先于接口堆叠
- 启动和电源优先于高速外设
- DDR 参考设计优先于自由发挥
- 任何不能解释清楚的接口都应保持 `NEED_VERIFY`

主要风险：

- `DDR` 拓扑偏离参考设计会直接影响可启动性
- `PMIC` 选择和时序不明确会影响整板稳定性
- `RGMII` 和 `USB` 的物理实现会影响后续调试效率
- 机械尺寸和散热边界可能反过来约束接口数量
