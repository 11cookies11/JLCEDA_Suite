# 14 DDR 参考设计采集清单

Status: Draft

## 目的

在正式扩展 LPDDR4 拓扑之前，先把参考设计里必须采集的关键信息列清楚，避免把骨架网误当成完整 DDR 设计。

## 需要采集的信息

- `U3` 的最终器件候选和封装确认。
- H618 到 LPDDR4 的完整 pinmap 归属。
- 数据线、地址线、控制线、时钟、复位和校准相关信号的参考连接方式。
- `+1V2_DDR`、`+0V9_DDR` 的电源归属、去耦分组和布局规则。
- 是否存在额外的参考电压、终端或偏置网络。
- DDR 区域的走线层、长度匹配、参考平面和禁布区约束。

## 采集顺序

1. 先确认器件与封装。
2. 再确认 SoC 到 DDR 的完整引脚归属。
3. 再确认电源、去耦、参考电压和复位逻辑。
4. 最后确认版图约束、走线规则和禁布区。

## 建议输出格式

- 每条信息都写成“来源 + 结论 + 影响”三段式。
- 结论必须能直接写回 `source/circuit-model.source.json`。
- 如果暂时无法确认，就标成 `need-verify`，不要用猜测填空。

## 当前模型的边界

- 当前模型只保留 5 条 LPDDR4 骨架网。
- 这些骨架网只能说明“存在 DDR 约束域”，不能说明完整拓扑已经完成。
- 在参考设计未确认前，不应把这些骨架网扩展成伪完整 DDR。

## 交付要求

- 参考设计信息应能直接写回 `source/circuit-model.source.json`。
- 每条新补充的 DDR 网络都应有明确来源说明。
- 在没有参考设计依据前，不扩展到更多信号。
