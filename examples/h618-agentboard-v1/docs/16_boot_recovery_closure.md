# 16 启动与恢复闭环方案

Status: Draft

## 目标

把 `MicroSD / SPI NOR / FEL` 三条路径收口成一套完整、可解释、可恢复的启动闭环。

## 当前结论

- `MicroSD` 是 V1 的首选启动介质。
- `SPI NOR` 是备用启动和恢复存储。
- `FEL / BOOT` 是最低层的人工恢复入口。
- 三条路径必须同时存在，不能互相替代到只剩一条。

## 角色定义

1. `MicroSD`
- 首次上电、bring-up 和日常开发的默认启动路径。
- 适合快速刷写、更新和调试。
- 应当优先保证可读、可写和稳定识别。

2. `SPI NOR`
- 备用启动路径和恢复介质。
- 可放置最小化的恢复镜像或板级 bring-up 固件。
- 适合在 MicroSD 失败时提供第二条路径。
- `WP#` 和 `HOLD#` 应默认上拉到 `+3V3`，避免恢复闪存进入写保护或暂停态。

3. `FEL / BOOT`
- 最底层人工恢复入口。
- 用于启动链失败、镜像损坏或需要外部刷写时进入恢复模式。
- 必须和串口调试一起工作，方便定位问题。

## 闭环原则

- `MicroSD` 失败后，必须还能尝试 `SPI NOR`。
- 两者都失败时，必须还能进入 `FEL`。
- `RESET_N`、`BOOT0`、`FEL` 和串口日志必须放在同一套恢复思路里看待。
- 恢复路径不应依赖未落实的高风险外设。
- MicroSD 的 `CMD` 与 `DAT0-DAT3` 应保持默认上拉，避免首启时出现悬空态或卡识别不稳。

## 需要落实的细节

- `BOOT0` 的默认状态和手动强制方式。
- `FEL / BOOT` 按键或跳帽是否保留。
- `SPI NOR` 中放置何种最低限度的恢复内容。
- `MicroSD` 的 CMD / DAT 线是否采用默认上拉以及阻值范围。
- `MicroSD` 作为首选启动介质时的软件加载顺序。
- 恢复失败后的串口提示和人工操作顺序。

## Bring-up 顺序

1. 先验证电源和 `UART0`。
2. 再验证 `MicroSD` 可启动。
3. 再验证 `SPI NOR` 可作为恢复路径。
4. 最后验证 `FEL` 可强制进入恢复模式。
