# 07 Bring-up 计划

Status: Draft

目标：

- 按最小风险顺序把板子点亮
- 优先验证电源、串口、启动存储和恢复入口
- 每一步都保留清晰的回退路径

阶段 1：上电前检查

- 检查板上短路和极性
- 检查 `J1` 输入路径和保护器件
- 检查 `U1`、`U2`、`U3` 周边无明显装配错误
- 检查测试点和调试口可接触

阶段 2：首次上电

- 先只接限流电源
- 观察 `+5V_IN`、`+5V_SYS`、`+3V3`、`+1V8`、`+1V1_CORE`、`+1V2_DDR`、`+0V9_DDR`
- 确认无异常发热
- 确认电源时序符合预期

阶段 3：串口验证

- 连接 `J3`
- 确认 `UART0` 有早期日志
- 记录 BootROM、PMIC 和启动介质相关信息
- 如果没有日志，先回到电源和复位检查

阶段 4：恢复入口验证

- 验证 `RESET`
- 验证 `FEL / BOOT`
- 确认可以从恢复模式重新进入下载或调试流程

阶段 5：启动介质验证

- 先验证 `MicroSD`
- 再验证 `SPI NOR`
- 记录默认启动路径和备份路径行为

阶段 6：基础外设验证

- 验证 `Ethernet`
- 验证 `USB Host`
- 验证 `GPIO / UART / I2C / SPI` 扩展口
- 先做连通性，再做速率和稳定性测试

阶段 7：风险回收

- 记录所有失败点和复现条件
- 把问题分为电源、启动、DDR、外设和布局五类
- 为每个问题准备修板或软件补救方案

Bring-up 原则：

- 每次只验证一条主线
- 先让板子可恢复，再让板子可用
- 先验证调试口，再碰复杂外设
- 所有偏差都要记录到 `where` 或 bring-up 日志中

待确认项：

- 首次上电所用的限流值
- 是否需要串口转接板或专用治具
- `MicroSD` 和 `SPI NOR` 的最终烧录流程
- 是否需要在首轮 bring-up 前先准备补丁包
