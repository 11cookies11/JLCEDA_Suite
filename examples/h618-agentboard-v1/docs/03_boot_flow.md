# 03 启动链

Status: Draft

目标：

- 明确第一版板子的启动优先级
- 把 DDR 依赖、启动存储和恢复入口放在同一条链路里管理
- 让原理图、软件 pinctrl 和 bring-up 记录都能引用同一份定义

启动优先级：

1. `MicroSD` 主启动
2. `SPI NOR` 恢复或备用启动
3. `FEL` 低层恢复入口

启动链草案：

- 上电后 `U1` 先建立基础电源和关键时序
- `U2` 完成最小复位与时钟稳定后进入 BootROM 阶段
- BootROM 优先尝试板级默认启动路径
- 若 `MicroSD` 不可用，则由 `SPI NOR` 作为恢复介质
- 若两者都失败，则通过 `FEL / BOOT` 进入外部恢复流程

MicroSD 启动路径：

- `J2` 是第一版的主要启动存储
- 该路径必须能支持开发、刷机和快速恢复
- 作为 bring-up 的首选启动介质
- `CMD` 与 `DAT0-DAT3` 需要默认上拉，保证卡座在上电和枚举阶段处于稳定定义态
- `J3` UART0 调试口必须在启动早期即可输出日志，作为第一条软件可见反馈路径

SPI NOR 角色：

- `U4` 用于恢复、救砖和备用引导
- 也可作为量产阶段的最小启动介质
- 在软件侧应保留独立识别和升级流程

FEL / BOOT 角色：

- `SW2` 提供手动进入恢复模式的入口
- 该路径用于启动失败时的兜底恢复
- 必须与串口调试一起工作，便于定位问题
- `SPI NOR` 的 `WP#` / `HOLD#` 也应保持默认高电平，避免恢复路径被意外锁定

DDR 约束：

- `U3` 必须参考成熟的 H618/H616 设计
- `+1V2_DDR` 和 `+0V9_DDR` 的拓扑必须和参考设计保持一致
- DDR 相关的布局、走线、去耦和上电时序不能自由发挥
- 第一版只允许在参考设计明确的前提下推进

启动与 DDR 的关系：

- DDR 是启动链能否进入 Linux 的前置条件
- 如果 DDR 初始化失败，启动存储再正确也无法进入系统
- 因此 DDR 约束的优先级不低于启动介质本身

Bring-up 顺序：

1. 验证 `+5V_IN`、`+3V3`、`+1V1_CORE`、`+1V2_DDR`、`+0V9_DDR`
2. 确认 `UART0` 可以输出早期日志
3. 验证 `FEL` 可进入恢复模式
4. 确认 `MicroSD` 可被优先识别
5. 验证 `SPI NOR` 的备用启动或恢复逻辑
6. 再进入 DDR 初始化和 Linux 启动验证

实现原则：

- 启动链必须简单、可解释、可恢复
- 不要把启动成功建立在未确认的复用脚上
- 任何和 DDR 相关的决定都必须能追溯到参考设计
- 启动存储和调试入口优先于扩展功能

待确认项：

- 最终 MicroSD 启动方案
- SPI NOR 在 V1 中的具体启动角色
- FEL 进入方式是否需要额外按键或跳帽
- DDR 参考设计的最终来源
