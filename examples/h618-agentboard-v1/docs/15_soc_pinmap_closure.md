# 15 SoC Pinmap 收口方案

Status: Draft

## 目标

把 Allwinner H618 的 SoC 侧引脚归属收口到“可以进入正式原理图捕获”的状态。

## 当前结论

- `U2` 的功能分组已经足够明确。
- V1 不再接受新的大范围功能新增，只允许在已有分组内微调。
- 需要落实的是：启动脚、调试脚、电源控制脚、外设总线脚和高速接口脚。

## 已经明确的功能分组

1. 调试串口
- `UART0 TX/RX`
- 对应 `J3` 调试口
- 目标是保证最早期日志输出始终可用

2. 启动与恢复
- `RESET_N`
- `BOOT0`
- `FEL`
- 这三类信号必须和电源、按键、恢复流程联动

3. 电源控制
- `PMIC_SCL`
- `PMIC_SDA`
- `PMIC_INT_N`
- `PWRON`
- 这些信号构成 SoC 与 PMIC 的基础控制闭环

4. 时钟
- `24MHz` 主晶振
- `32kHz` RTC 晶振
- 这是 SoC 启动和低功耗状态的基础前提

5. 启动存储
- `SDIO`
- `SPI0`
- `MicroSD` 和 `SPI NOR` 的角色不能混淆

6. 主外设
- `RGMII`
- `USB0`
- `HDMI`
- 这三组高速接口必须和板级布局同步落实

7. 扩展口
- `J4` 26Pin 扩展口已经给出当前映射草案
- 相关复用脚仍需与 DTS 和最终原理图一致

## 落实原则

- 不允许再新增与 V1 无关的功能分组。
- 已有分组内如果要改，必须同时更新 `source/circuit-model.source.json`、引脚文档和后续原理图。
- `U2` 的功能分组一旦落实，后续的软硬件协同只允许在同一组内调整复用，不允许推翻总体拓扑。

## 需要确认的内容

- SoC 封装与 ball map 是否与最终参考设计完全一致。
- `BOOT0` 和 `FEL` 的最终默认状态。
- `PMIC` 相关控制脚是否需要额外上拉或去耦。
- `RGMII` 与 `USB0` 是否有额外的参考设计约束。
- `HDMI` 相关输出是否需要补充 ESD 或电源联动信号。
