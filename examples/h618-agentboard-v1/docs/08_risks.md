# 08 风险

Status: Draft

目的：

- 把当前设计风险分成“可以继续推进”和“必须等参考设计确认”两类
- 避免把所有不确定项都混成一个列表
- 让原理图、PCB 和 bring-up 的决策边界更清楚

可以继续推进的风险：

- `UART0` 调试口仍需要保持板边可达
- `RESET / FEL` 需要在布局阶段保持易操作
- `MicroSD` 和 `SPI NOR` 的软件角色需要保持清晰
- `RGMII` 和 `USB` 需要保持短走线和连续参考平面
- `HDMI` 需要保持接口、ESD 和供电边界清楚

必须等参考设计确认的风险：

- `DDR` 初始化失败
- `PMIC` 和上电时序不匹配
- `U2 H618` 最终 pinmap 偏差
- `LPDDR4` 拓扑偏离成熟参考板
- `FEL / BOOT` 默认状态与布局后恢复路径冲突
- `SPI NOR` 与 `MicroSD` 的最终启动优先级需要与软件一致

伴随风险：

- 硬件和 DTS 不一致
- 复用脚在硬件和软件之间的职责分配不一致
- 网口、USB 和 HDMI 的器件级细节影响最终布线密度

处置原则：

- 可以继续推进的风险，优先在文档和布局中消解
- 必须等参考设计确认的风险，不在没有依据时自由发挥
- 所有风险都要能回溯到 `circuit-model.json` 或需求文档

## 阶段 4 额外提示

- `RGMII / USB Hub / HDMI / USB-C` 仍应按参考捕获顺序推进。
- 在 [高速接口参考设计采集清单](15_high_speed_reference_capture_checklist.md) 完成前，这些接口的器件细节不要被当成已定版。
- 任何新的接口风险都应该直接回写到 `circuit-model.json`，避免只停留在文档里。
