# 00 Requirements

Project: ai-memory-badge-v1

Status: Draft

## Product Goal

构建一款胸牌 / 夹子形态的全天候随身 AI 记忆器。设备负责低功耗人声捕捉、本地缓存、隐私可控和稳定同步；AI 转写、摘要、检索和长期记忆管理由手机、电脑或云端完成。

V1 不是完整 AI 终端，而是可靠的随身音频采集层。

## Target User Experience

- 用户可以把设备夹在衣服、包带或挂绳上，一整天携带。
- 设备默认处于低功耗监听状态，检测到人声后录音。
- 用户可以按键标记当前片段为重要内容。
- 用户可以通过物理静音开关明确关闭录音能力。
- 用户可以通过 USB-C 或 Wi-Fi 同步当天音频。
- 用户可以看到录音 / 静音 / 同步 / 低电量等基础状态。

## V1 Functional Requirements

- 人声触发录音，使用 VAD 降低无效录音和功耗。
- 支持手动录音或重点片段标记。
- 支持 USB-C 充电、调试和有线导出。
- 支持 Wi-Fi 上传音频片段。
- 支持 BLE 预留或基础配网能力。
- 支持本地存储至少 24 小时的人声触发音频片段。
- 支持电池电量检测。
- 支持录音状态 LED 指示。
- 支持物理静音开关，静音状态必须可见。
- 为本地加密预留硬件和固件接口。

## Non-Functional Requirements

- 续航优先：目标日常佩戴 12-16 小时。
- 待机目标：2-5 天，取决于固件低功耗策略。
- 原型板优先：可调试、可测量、可返工。
- 音频目标：近场人声清晰，优先覆盖胸前 0.5-2 m 场景。
- 隐私目标：用户能明确知道设备是否可能录音。
- 维护目标：核心器件应尽量选择常见、可采购、资料充足的型号。

## Hardware Constraints

- 主控优先选择 ESP32-S3 裸芯片，兼顾 Wi-Fi、BLE、USB、I2S 和后续产品化尺寸。
- 裸芯片设计必须包含外部 Flash/PSRAM、晶振、RF 匹配/天线、启动下载电路和完整电源去耦。
- 麦克风采用 2 颗数字 MEMS I2S 麦克风。
- 存储优先采用 microSD，降低早期容量风险。
- 供电采用单节锂电池，USB-C 充电。
- 第一版允许较大 PCB，优先保证 bring-up、射频可调试性和功耗测量。

## Out Of Scope For V1

- 设备端大模型推理。
- 设备端完整转写。
- 小型化量产外壳。
- 多麦克风复杂波束成形。
- 蜂窝网络。
- 无线充电。
- 医疗、安防或法律取证级录音能力。

## Open Questions

- 是否需要默认加密所有本地音频，还是 V1 仅预留加密能力？
- 是否需要硬件安全芯片保存密钥？
- 是否需要独立 RTC 来保证离线时间戳准确？
- 是否需要触摸交互，还是只保留实体按键 / 开关？
- 是否需要扬声器或蜂鸣器，还是只用震动和 LED？
