# 版本管理策略

## 版本号约定

当前仓库使用语义化版本号（SemVer）管理插件版本，格式为 `MAJOR.MINOR.PATCH`。

- `MAJOR`：桥接协议、命令载荷或运行方式出现不兼容变更
- `MINOR`：新增向后兼容的桥接能力、EDA 适配能力或工作流能力
- `PATCH`：修复缺陷、完善文档、补充测试或修正非破坏性实现细节

## 版本同步位置

每次发布前，至少同步检查以下两个位置：

1. `package.json` 中的 `version`
2. `extension.json` 中的 `version`

这两个版本应保持一致，避免生成的 `.eext` 包版本与仓库元信息不一致。

## 建议发布节奏

- 完成一个可验证的能力切片后再提升版本
- 未经过 JLCEDA 实机导入验证的版本，不建议标记为稳定发布
- 如果只新增文档或测试，且不改变对外行为，优先提升 `PATCH`

## 发布前核验命令

执行以下命令确认当前版本可发布：

```bash
npm run release:check
```

该命令会依次执行：

1. `npm run lint`
2. `npm run build`
3. `npm run smoke-test`

## 当前阶段建议

当前仓库仍处于能力验证和协议收敛阶段，建议：

- 继续使用 `0.x.y` 版本段
- 只有在桥接协议、菜单入口、核心只读/写入工作流稳定后，再考虑进入 `1.0.0`
